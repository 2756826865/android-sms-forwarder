## 🔄 双模式架构与自由切换

本项目采用 **「经典短信模式」** 与 **「开发模式（SMS Gateway 工作台）」** 双视图架构，两种视图共用底层短信数据和配置，刷新效果受系统权限及同步状态影响：

| 模式 | 核心定位 | 适用场景 | 切换方式 |
| :--- | :--- | :--- | :--- |
| **📱 经典模式 (Classic)** | 完整的默认短信应用体验，支持气泡会话、双卡收发、批量群发与轻量级转发。 | 主力机日常发信收信、备用机日常短信管理。 | 主界面右上角菜单 → 点击 **「切换到开发版工作台」**。 |
| **🖥️ 开发模式 (SMS Gateway)** | Jetpack Compose 现代化工作台，提供短信会话、运行大盘、通道管理与分类设置。 | 备用机做短信转发服务器、极客监控、系统集成。 | 开发版任意界面顶栏 → 点击 **「返回经典版」**。 |

## 下载与开始使用

1. 从 [Releases](https://github.com/2756826865/android-sms-forwarder/releases) 下载正式 APK 并安装；同签名升级通常可保留数据，升级前可先备份配置。
2. 按提示授予读取、接收短信等所需权限；需要发送短信时授予发送权限，需要通知时允许通知权限。联系人权限用于姓名和头像显示。
3. 作为默认短信客户端使用时，在系统中选择本应用为默认短信应用；仅用于转发时，也需检查系统实际授予的接收能力。
4. 在「通道」创建并配置通道实例，先测试，再设置转发目标与规则。测试任务被提交或通道受理不代表接收端已收到。
5. 历史短信可从信息页菜单执行全量同步。同步将系统可读取的 SMS/MMS 导入应用本地数据，不上传到开发者服务器，也不会自动重新转发历史消息。

安装、权限与排障细节见 [使用教程](docs/user-guide.md)。

## 🌟 核心功能特性

### 1. 开发版四个导航入口（Compose）

- **信息**：短信会话、搜索、历史同步与新建短信。
- **大盘**：运行状态、今日短信与转发四列统计、最近记录及详情。
- **通道**：转发通道实例管理，以及电量提醒、定时心跳等功能配置；规则与模板通过相关入口管理。
- **设置**：主题、短信显示、保活、备份、诊断、教程与关于；详细诊断不再堆放在首页。

### 2. 支持的通道

可创建多个通道实例，并为不同功能选择发送目标。以下按通道类型列出，兼容标识不重复计算；各提醒功能可选范围以对应页面为准。

| 通道 | 说明 |
| :--- | :--- |
| 微信测试号 | 使用公众号测试号的模板消息推送，需配置 AppID、AppSecret、模板 ID 和 OpenID。 |
| PushPlus 微信推送 | 通过 PushPlus 服务推送到配置的接收目标。 |
| WxPusher 消息推送 | 通过 WxPusher 应用推送消息。 |
| QQ 消息（Qmsg / OneBot） | 通过 Qmsg 或兼容 OneBot 的服务发送 QQ 消息；需要自行配置相应服务。 |
| 企业微信应用号 | 通过自建应用向指定接收人发送消息。 |
| 企业微信群机器人 | 通过群机器人 Webhook 推送。 |
| 企业微信智能机器人（长连接） | 关联已配置的长连接来源实例，向指定会话发送消息。 |
| 飞书自建应用 | 配置应用凭据和接收目标，通过应用发送消息。 |
| 飞书群机器人 | 通过群机器人 Webhook 推送，支持签名配置。 |
| 钉钉群机器人 | 通过群机器人 Webhook 推送，支持加签配置。 |
| Bark（iOS） | 配置服务地址和设备 Key，向 Bark 客户端推送。 |
| WebSocket 客户端 | 连接配置的 WebSocket 服务端发送消息。 |
| Telegram 机器人 | 配置 Bot Token 和 Chat ID，支持自定义 API 地址。 |
| Discord 群机器人 | 通过 Discord Webhook 推送到频道。 |
| 腾讯云自定义告警 | 通过配置的自定义告警 Webhook 推送。 |
| 邮件（SMTP） | 通过 SMTP 服务器发送邮件，支持 SSL/TLS 配置。 |
| 短信直发（SIM） | 使用手机 SIM 卡向目标号码发送短信，按配置选择发送卡，并受系统发送权限及运营商规则限制。 |
| 自定义 Webhook | 支持 GET/POST/PUT/PATCH、自定义请求头和消息模板，对接自建或第三方 HTTP 接口。 |
| Gotify | 向配置的 Gotify 服务发送推送。 |
| ntfy | 向指定服务的 Topic 发布消息。 |
| Server酱³ | 通过配置的 SendKey 推送。 |
| 群组聚合消息 | 将多个通道实例组合为一个转发目标；这是应用内聚合方式，不是独立推送服务。 |

### 3. 📡 7 类远程控制发信来源 (Remote SMS Command Hub)
支持通过远程接收指令（如 `/发信 [SIM1|SIM2|默认] 13800138000 短信内容`）驱动备用机本地 SIM 卡发送短信：
- ✈️ **Telegram Bot 模式**：基于 `getUpdates` 长轮询与自定义反代 Host 支持，支持 ChatID/UserID 白名单，回执原路直接响应；
- 🔌 **WebSocket 全双工模式**：支持与服务端全双工长连接，服务端主动下发 `send_sms` JSON 载荷，发信及送达状态通过同一连接实时上推；
- 📌 **钉钉 Stream 模式**：无需公网 IP，通过钉钉官方长连接协议接收机器人消息指令；
- 🕊️ **飞书 Stream 模式**：通过飞书 OpenAPI WebSocket 长连接订阅机器人事件；
- 💬 **企业微信智能机器人官方长连接 (WeCom WebSocket Bot Stream)**：
  - **免公网 IP / 免配置回调 URL**：基于腾讯企业微信官方 SDK (`aibot-node-sdk`) 协议标准，通过官方长连接端点直连；
  - **双向发信与原路回执**：凭 `bot_id` 与 `secret` 握手鉴权，群内或私聊中发送 `/发信 10086 查询` 驱动备用机发信，并原路接收发送状态及送达回执；
- 📧 **邮箱 IMAP/SSL 轮询**：支持 QQ/163/Gmail 等邮箱轮询与发件人白名单安全校验；
- 📱 **短信指令**：监听本机收到的指令短信，按授权设置和发送卡配置执行。
- 🧾 **回执与防重**：网络机器人来源可原路回复；短信与邮箱来源使用配置的转发目标。系统提交、发送回调和运营商送达报告是不同阶段。QQ / OneBot 当前仅用于通知转发。

> ### 💡 钉钉、飞书与企业微信机器人配置指南（单向推送 vs 远程发信）

> | 功能类型 | 使用场景 | 对应模式 | 获取与配置方法（⚠️ 注意客户端差异） |

### 4. 🤖 智能防对轰「短信自动回复」引擎
- **精准触发**：支持指定发件人号码过滤、关键词/排除词过滤、指定发信卡槽。
- **4 重防对轰保护**：
  - **自由冷却周期**：支持 **1 分钟到任意天数**（如 1 分钟、10 分钟、24 小时或不限制）自定义设置；
  - **发信延迟**：0~60 秒模拟真人发信；
  - **日上限熔断**：防止短时间内大量回复消耗话费；
  - **回执上报**：自动记录并推送执行回执。

### 5. 消息模板与智能变量插值
- **两版无缝共享**：经典版「设置 -> 功能 -> 消息模板」直接直通开发版「规则工坊」，两种界面共用配置。
- **支持 18 大动态模板变量**：
  - `{{CODE}}` 智能提取验证码、`{{FROM}}` 发信号码、`{{SMS}}` 短信正文、`{{RECEIVE_TIME}}` 接收时间、`{{DATE_YMD}}` 仅日期、`{{DATE_HMS}}` 仅时间、`{{CONTACT_NAME}}` 联系人姓名
  - `{{SIM_SLOT}}` 卡槽标识、`{{SIM_INDEX}}` 卡槽序号、`{{RECEIVER_NUMBER}}` 接收卡号
  - `{{DEVICE_NAME}}` 设备型号、`{{DEVICE_BRAND}}` 设备品牌、`{{BATTERY_INFO}}` 电池电量状态、`{{BATTERY_PCT}}` 电量百分比、`{{IP_LIST}}` 当前 IP 地址、`{{NET_TYPE}}` 网络类型、`{{APP_VERSION}}` 应用版本、`{{CURRENT_TIME}}` 当前时间
- **智能验证码提取沙箱**：内置正则与前后瞻匹配引擎，精准提取 4~8 位数字验证码。

### 6. 🛡️ 双广播容灾降级与数据备份
- **双广播容灾**：`SMS_DELIVER` + `SMS_RECEIVED` 双通道监听，结合 SHA-256 全局指纹去重，非默认短信状态下提供补充接收路径；实际能力仍受系统广播、权限及厂商策略限制。
- **一键配置备份与还原 (`ConfigBackupHelper`)**：支持将 12 大通道凭据、智能规则、消息模板一键导出为结构化 JSON 文件并支持快速导入。

### 7. 离线事务队列与自愈恢复引擎
- **Outbox 事务队列 (`OutboxDispatcher`)**：断网或息屏休眠时自动暂存（`PENDING / RETRY / FAILED`），网络恢复后按指数退避策略自动重试。
- **Recovery 自动补偿 (`RecoveryEngine`)**：后台周期性巡检与自愈补偿机制，对符合条件的失败记录尝试补偿；效果受任务状态与系统后台策略影响。

### 外观与设置

- **主题**：支持 Miuix / Material 界面风格、跟随系统或手动深浅模式、强调色及 Monet 配色。默认橘红，Monet 默认关闭；保留用户已保存的选项。
- **预览与导航**：主题页用示例大盘实时预览配色，支持悬浮底栏、模糊及设备支持的玻璃效果。信息页新建短信按钮固定为绿色。
- **分类入口**：外观与主题、短信与显示、保活设置、备份与恢复、诊断与报告、帮助与反馈、完整设置及关于。
- **日志**：支持预览、保存和分享发送日志与诊断信息。发送日志包含保留的持久化发送操作和转发历史，受保留范围限制；内存日志不是完整发送历史。
- **黄页**：支持服务号码和正文品牌签名识别、名称及 Logo 展示；私人手机号增加匹配保护，识别结果不代表身份认证。

## 🛡️ 隐私、安全与兼容性

### 1. 硬件级安全加密 (Keystore AES-GCM)
- 所有通道密钥（AppSecret、Bot Token、Headers 等）均采用 **Android Keystore AES-GCM 硬件级加密** 存储；
- 具备旧版本无缝平滑迁移与硬件不可用时的内存加密自动回退机制。

### 2. 系统兼容性
- 对旧系统事件订阅、默认短信角色和国内 ROM 权限差异进行适配。不同厂商和 Android 版本的行为可能不同；遇到异常请附应用版本、系统版本及脱敏诊断信息反馈。

### 3. 多卡分流与低电量告警
- 重构底层 `SubscriptionResolver`，适配小米 HyperOS、华为/荣耀 EMUI/MagicOS、OPPO/vivo 等设备的双卡信息；实际可用卡槽和权限以系统返回为准。
- 支持低电量智能检测与告警分流推送。

## ⚙️ 息屏保活与后台设置指南

为了确保备用机或主力机在长时间息屏休眠时稳定转发，请确保开启以下系统权限（可在应用内开发版「设置 → 保活设置」或经典版对应系统兼容入口中一键跳转设置）：

1. 🔋 **电池优化**：设置为 **「无限制」 / 「允许后台高耗电」**；
2. 🚀 **自启动权限**：设置为 **「允许自启动」 / 「允许关联启动」**；
3. 🔒 **后台多任务加锁**：在多任务界面给应用卡片加上 **「锁头 🔒」**；
4. 📱 **设为默认短信应用**：推荐设置为系统默认短信 App，以获得系统默认短信角色所需的收发能力；默认角色不等于后台保活保证。
