# SMS Forwarder

**Android 短信管理与多渠道转发**

<p align="center">
  <img src="graphics/icon.webp" width="112" alt="SMS Forwarder 图标" />
</p>

在手机上管理短信，将短信和通知转发到指定渠道，也可以通过授权的远程指令调用本机 SIM 卡发送短信。

**经典短信界面与开发版工作台集成在同一个 APK 中**，共用短信数据和转发配置，可在应用内切换，无需分别安装。

## 选择适合自己的界面

| 界面 | 主要用途 |
| --- | --- |
| 经典短信界面 | 查看会话、收发短信、管理双卡短信和日常设置 |
| 开发版工作台 | 集中查看运行概况，管理转发通道、规则、模板、远程来源与诊断 |

两种界面共用同一套后台逻辑；切换界面不会另外创建一套转发服务。

## 可以做什么

- **短信管理**：会话列表、短信收发、双卡选择、定时发送及自动回复。
- **多渠道转发**：管理多个渠道实例，为每个实例单独设置凭据和启用状态，按规则选择目标。
- **规则与模板**：按号码、内容和卡槽等条件处理消息，使用短信正文、验证码、时间、联系人、设备和 SIM 信息等模板变量。
- **通知转发与提醒**：授权后转发所选应用通知，并配置未接来电、电量等提醒；各项能力受对应权限和设置约束。
- **远程发送短信**：通过已启用的远程来源接收指令，校验授权后调用本机 SIM 卡发送，并记录执行结果。
- **备份与诊断**：导入导出配置，查看转发记录、运行日志及权限状态，辅助定位问题。

### 转发渠道

支持邮件 SMTP、PushPlus、微信测试号、Telegram、钉钉、飞书、企业微信、Bark、Gotify、Discord、QQ / OneBot、自定义 Webhook 等渠道。具体类型和配置项以所安装版本的通道管理页面为准。

**通知推送和远程指令是不同功能**：配置一个群 Webhook，并不代表机器人能够接收群里的发信命令。QQ / OneBot 当前用于通知转发。

### 远程指令来源

| 来源 | 接收方式 |
| --- | --- |
| 短信指令 | 收到短信后检查前缀和授权，无需网络长连接 |
| 钉钉 Stream、飞书、企业微信智能机器人、WebSocket | 启用对应来源后维持网络连接 |
| Telegram | 长轮询 |
| 邮箱 | IMAP 轮询 |

远程短信指令示例：`/发信 10086 查询`。具体前缀、卡槽和白名单按来源配置；普通推送渠道不会自动启用远程发信。

## 后台运行方式

**正式版 101702** 保留其现有后台策略；以下按需默认行为属于 **101703 测试构建**：

- 未设置过保活选项时，默认按需运行：短信到达后启动短时处理，完成后结束；需要联网的投递交给任务调度执行。
- 已明确保存的保活开关继续生效；关闭“兼容保活模式”可使用按需方式。
- 启动或处理异常时尝试最小处理和补偿；断网投递按任务约束等待并退避重试，保留低频漏收补偿。
- 远程来源独立控制：只开启短信指令不需要网络长连接，开启网络来源才运行对应监听。
- 对锁屏后出现漏收的设备，可以开启兼容保活，并检查系统自启动、后台运行和电池限制。

常驻服务、任务调度和默认短信身份都不能保证绕过所有厂商限制；系统设置中的“强行停止”也不能保证自动恢复。具体功耗和可靠性需要在目标手机上验证。

## 101703 测试版重点更新

- 按需短信处理与异常补偿，兼容保活恢复时重新校验设置。
- 减少无消息时的数据读取和不必要的模板信息查询。
- 转发记录改为数据库存储与分页、事件刷新，支持仅重试原通道。
- 通道组支持并行、成功即停、失败即停；投递结果未知时避免自动重复发送。
- Webhook 支持响应文本及 JSON 字段成功校验。
- 新增手动检查更新，点击后才检查；QQ群入口支持复制群号并打开入群链接。

## 开始使用

1. 安装 APK，按需要设为默认短信应用并授予相关权限。
2. 添加转发渠道并使用“测试”确认凭据和目标正确。
3. 设置转发规则、消息模板及 SIM 卡信息，再发送一条真实短信验证完整链路。
4. 如需远程发信，单独配置远程来源、指令前缀和授权白名单。
5. 锁屏测试后再决定是否开启兼容保活及调整系统后台限制。
