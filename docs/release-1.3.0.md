# 短信转发器 1.3.0

发布日期：2026 年 11 月 18 日 · 版本代码：1300

本版本为全链路架构升级与性能飞跃大版本：打通系统短信通知 0ms 零延迟直入标准短信规则引擎秒发，建立广播与通知双向 CAS 原子防重与合成消息全生命周期自愈机制，重构 Room 数据库索引与批量事务以支撑 3 万+ 条短信丝滑运行，并全面加固规则隐私脱敏、来电转发与无障碍安全填充。

## 主要更新

- **系统短信通知 0ms 零延迟秒发（直通标准短信规则引擎）**：
  - 针对 ColorOS 17、OriginOS、MIUI/HyperOS、Flyme 等强行收回默认短信角色或开启「验证码安全保护」屏蔽短信广播的场景，收到系统短信通知时（即使用户未开启第三方应用通知转发），**0ms 零延迟**直接走标准短信转发管线（黑名单过滤 ➔ `ForwardingRuleEngine` 规则匹配 ➔ 正则内容清洗 ➔ 单动作自定义模板 ➔ `{{CODE}}` 提取与隐私脱敏 ➔ 通道秒发）。
  - **双向毫秒级 CAS 原子防重**：在 `SmsReceiver` / `SmsFallbackReceiver` 广播入口第一行（`T=0ms`）立即登记内存指纹，与通知兜底双向互斥——无论系统先发广播还是先弹通知，先到者 0ms 瞬间秒发，后到者自动跳过重复外部推送。
- **净化系统短信识别边界与合成会话自愈**：
  - 从系统短信包名集合中剔除 `com.xiaomi.xmsf`、`com.heytap.mcs`、`com.coloros.mcs` 等非短信推送守护框架，并前置过滤常驻通知（`FLAG_ONGOING_EVENT`）、前台服务与“正在发送/正在备份”等状态通知，根治非短信通知污染本地短信会话列表。
  - 当系统短信库真实记录稍后落库时，自动清理并原地替换临时合成记录（`8_000_000_000_000L`）与孤立合成会话；修复会话详情页刷新后保底合成短信消失的问题，并支持在非默认短信模式下直接删除或移入回收站本地/合成会话。
- **3 万+ 大数据量性能飞跃与 Room 数据库优化**：
  - 新增 `messages(type, date)` 复合索引（Room v17 自动平滑迁移），彻底消除看板统计与保底排重的 3 万行全表扫描。
  - 将 `ConversationsDao.getAllRegularWithLatestSnippet` 中的逐会话 `COUNT(*)` 与 `MAX(date)` 子查询重写为 `EXISTS` 与索引倒序 `LIMIT 1`。
  - 将会话刷新与全量同步中的上千次逐行独立事务合并为单次批量事务（同时完整保留用户自定义会话标题），消除磁盘 fsync 与 UI 重组风暴。
- **转发引擎、来电转发与无障碍安全填充加固**：
  - **规则自定义模板隐私脱敏**：修复规则/动作独立模板未经过 `PrivacyDataMasker` 的漏洞，确保手机号与验证码脱敏在所有模板模式下 100% 生效。
  - **定时报活与低电量告警修复**：透传 `bodyAlreadyRendered = true`，防止心跳报活与低电量告警被用户的 `{{CODE}}` 短信模板覆盖为空消息。
  - **来电转发增强**：严格执行「仅未接来电」开关并结合通话记录识别过滤用户主动挂断的来电；兼容模式下同步覆盖所有多实例通道。
  - **Telegram 反代与规则兼容**：为 Telegram 转发通道接入 `customHost` 自定义反代域名；修复 v1 规则升级时 `excludeKeywords` 失效问题；修复微信通知触发「转发后标记已读」在系统短信库创建幽灵空会话的问题。
  - **无障碍验证码防误填保护**：移除无特征盲取页面首个输入框的逻辑，在微信/QQ/飞书/钉钉/Telegram 等聊天应用中严格要求输入框具备验证码提示词才填充，杜绝验证码覆盖用户正在输入的聊天内容。

完整累计变更见 [CHANGELOG](https://github.com/2756826865/android-sms-forwarder/blob/v1.3.0/CHANGELOG.md)。
