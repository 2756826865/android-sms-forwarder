## 对实际分支的修正

### 历史同步

- 保留单次 SMS 查询和每 500 条写入。增加进程内互斥，避免首页、角色回调和手动按钮并行重复全量扫描。
- 不再忽略解析失败、MMS 查询失败及会话查询失败后报告全量成功。
- `getMMS` 新增可选 strict 入口，仅历史全量同步使用，其他调用维持原默认行为。
- 完整成功且读取到 SMS 后才写全量完成标记；首页不再把失败结果无条件标记完成。
- 无效 thread ID 计入失败并保留已写批次，不在只读历史同步中创建系统线程；后续可重新同步。
- 此同步入口不调用转发、自动回复、远程命令。相关已有启动恢复任务仍保持其原职责，不应拿全量历史同步作转发触发器。

### 收信与任务身份

输入分支 FULL 路径在非默认时返回 0，随后仍查询系统 thread 并失败；MINIMAL 仍通过异常表示非默认状态。本次改成明确只读接收，跳过系统线程创建和写入。每次写入重试前重新观察角色，处理中失去角色即转兜底。

新增独立 SQLite 身份别名表。广播与 Provider 记录关联成功时，共用 workId 和原接收时间；不创建占用系统 ID 空间的私有自增短信。应用列表由系统记录同步恢复。

对双方均有发送时间的记录要求发送时间相同。`date_sent=0` 时仅允许同号码/正文摘要、同订阅 ID、接收时间相差不超过 2 秒且候选唯一的关联；两个候选、未知订阅或超迟入库不强行合并。保存摘要、PDU 指纹和别名，不保存号码/短信原文。

明确边界：不能据此保证任意 ROM 严格一次投递。歧义或严重延迟仍可能重复，优先不吞掉真实短信。旧版本已经产生的两个独立发送任务不能被本表追溯合并。

恢复扫描改用正常/兜底路径相同的实例级入口，避免一条走 instance、一条走 legacy 类型。规则目标携带实际渲染内容及 rule/action ID。广播兜底关联的系统记录不额外消费可能收费的远程指令。

### 发送与重试安全

- 企微长连接的 `ack_timeout`、`invalid_ack`、`internal_error` 保留结果未知语义，停止自动重发；明确拒绝和未连接与之区分。
- 历史数据库 v3→v4 新增 sms_phase 和 queue_submissions，保留原日志、快照及旧防重表。
- 人工重试和自动修复先事务保存固定 UUID、完整 WorkData、原目标/内容与延迟，再提交 WorkManager；既有恢复事件继续同一个 UUID，无新常驻循环。
- 执行认领独立于入队认领；未证明安全的二次执行保持结果未知。只有明确处于正常重试或纯短信提交前准备状态的合法系统重试才可继续。
- SMS 收费保护库 v1→v2，旧 claim 迁移为 unknown，永不释放。新增提交边界回调位于实际 SmsManager API 之前、分片/PendingIntent 准备之后。提交前失败与提交后异常分开，结果未知不自动重发。
- MMS 仍走其原发送器，保留较保守的提交保护，不把它宣称为已实现精确 SMS 提交边界。
- 回执采用 URI + 本次操作 ID 关联；失败回执不被迟到成功或 Worker 结果覆盖。混合通道记录不会由单个 SMS 回执整体置成功。
- 重试界面先提示缺失快照或收费保护限制，动作反馈只说明检查请求，不声称已发送成功。

### 诊断与可选联系人

首页、短信接收/重试写入和角色变化广播记录默认身份观察结果；不申请/抢占角色。观察到变化的时间不是系统实际撤销角色的精确时间。

可选 Fossify 私有联系人 Provider 未安装时跳过其查询，系统联系人及号码兜底保留。此项是避免无效查询，不等同于证明此前崩溃由该 Provider 导致。
