# 短信直发重复扣费：防重复提交补丁（实现记录）

基线为 main `e0531e078935e3e2215608e263bb4d197a1a839f`，本轮与队列补丁整合到 `fix/forwarding-safety-completion`。原独立工作分支保留。以下为本地补丁验证记录，后续 `1.2.4(101901)` 的构建发布状态以 GitHub Actions / Release 为准。

## 已确认的源码风险

1. `MultiChannelForwardWorker` 的短信直发异常可能进入通用重试判断；非通道组任务重启也没有覆盖所有收费发送的持久化保护。
2. `ForwardSmsOutboxExecutor` 捕获异常后返回 Retry。短信已提交但随后写回日志等步骤出错时，可能被再次执行。
3. 插件路径原来主要检查可选发送观察记录中的 SENT/DELIVERED，不能替代在发送前持久化的去重认领。
4. 主转发路径缺少“发件人与目标相同”的回传拦截，存在简单互转循环的风险。

这些是代码依据，并非本次用户扣费事件已经抓到的根因。相同短信被重复提交、不同设备循环转发和长短信分段计费，需要结合用户反馈及发送记录区分。

## 本补丁

- 单独使用 `sms_direct_guard.db`，以原短信标识、接收时间与目标号码的哈希做唯一键。同一原短信经多个规则、通道实例或通道组发往同一号码时共用标记，避免换一条任务就绕过保护。在收费调用前提交认领事务，之后成功、异常或取消均不释放认领。清空转发展示日志不会清空该标记。
- 主转发、专用短信 Outbox 和短信插件均接入认领；Outbox 优先使用稳定投递 ID，缺失时使用真实任务 ID，两个 Outbox 路径共享同一去重键。
- 系统短信库写入失败的降级转发，改用原始 PDU 的号码、正文、发送时间和订阅标识生成指纹，不再用当前接收时间及正文 hashCode 作为任务标识；不同路由共享同一收费去重身份。没有可用 PDU 时间时使用 0，保守防重。同内容、同原始发送时间和同订阅的真正独立消息无法区分，可能被拦截。
- 旧格式降级队列没有稳定原短信身份时，停止收费发送，不把每条旧任务当成新短信收费。此限制不阻止该任务中的网络通道。
- 主转发的短信直发一旦开始处理，禁止进入通用自动重试。WorkManager 重试及历史上已经开始执行过的同一任务，均不再次发送收费短信。
- 短信直发 Outbox 异常终止自动重试；已有任务尝试记录或已有未确认的发送观察记录时保守拦截。
- 已尝试过的短信直发记录不能从日志再次提交；未开始执行的失败记录须先确认原系统任务失败或取消，保留原短信标识后重试，仍受同一认领保护。网络通道也须核对原任务已结束，并用持久化预约阻止重复点击；不取消网络发送功能。
- 主转发阻止把真实短信直发回原发件人，识别中国大陆手机号码的本地、+86、0086 和 86 常见形式；不是任意多设备环路检测。
- “提交 API 成功”不再记录为运营商最终送达；异常结果提示先核对收件端。

这是同一保护标识与目标组合的至多一次提交，代价是：认领后即使尚未真正发出便中断，也不自动补发。同一短信通过不同规则刻意重复发往同一号码，也会被拦截。用户明确发起的新测试、不同原短信及普通手动发短信仍可能产生费用。本补丁不会减少运营商对长短信分段的计费，也不能撤销已交给系统/运营商的短信；不改变普通手动发短信、远程控制发信、SIM 选择和网络转发的执行逻辑。该保护不承诺跨 Worker 与 Outbox 的任意独立投递 ID 自动归并，也不能跨清除应用数据保留标记。

## 验证

- 21 项 JVM 策略测试通过：重复执行、提交后异常、取消、存储故障、并发认领、号码归一化、回传识别、未知结果判定、原短信路由归并、短信 ID 复用、Outbox 投递标识、手动重试限制、新降级指纹与旧降级队列拦截。
- 4 项 SQLite 测试通过：并发唯一认领、数据库重开保留、事务回滚以及清理展示库不释放认领；使用生产建表语句。
- 提取实际 Worker 的短信直发方法，并编译实际两个 Outbox 执行器、短信插件及手动重试入口，在宿主替身环境完成 35 个场景检查。覆盖重启、旧尝试记录、回传、异常后执行、Outbox 交叉重复执行、同投递不同任务、降级指纹、手动重试核对与并发预约、原实例变更及恢复快照 UUID 不匹配拦截等；发送调用全部为计数替身，没有真实发送短信。
- 已将策略/SQL 回归纳入正式构建工作流的检查清单，未触发构建。
- 完整 APK 和 Android 真机验证未完成；本地缺少可用 SDK，下载补充也受网络阻断。上述宿主检查不能替代完整编译、厂商系统和运营商实测，不能据此保证用户当前设备已解决。

修复版真机验证前应关闭短信直发，先保留短信及转发日志。后续需核对当前安装版本、重复内容是否相同或逐次增长，以及运营商账单中的分段/发送次数；不要通过连续收费短信试错。
