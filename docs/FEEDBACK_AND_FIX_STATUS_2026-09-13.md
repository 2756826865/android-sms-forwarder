## 二、代码层定位结果

### F-2 页面抖动 — 根因已确认 ✅

**证据**：

1. `imePadding` / `setDecorFitsSystemWindows` / `enableEdgeToEdge` 在全 main 源集**零使用**（grep 无任何输出）
2. `AndroidManifest.xml:93` 仅一处 `windowSoftInputMode="adjustResize"`
3. Compose 输入页 `ui/compose/forwarding/ChannelHubScreen.kt`（图 2/3/4 对应界面）**完全没有 ime inset 处理**

**根因**：键盘弹起触发窗口 resize，但 Compose 侧未消费 ime inset；每次输入更新 state → 重组 → 布局重算 → 视觉上下抖动。

**修法**（三选一或组合）：
- 在输入页滚动容器加 `Modifier.imePadding()`
- 或 `Modifier.windowInsetsPadding(WindowInsets.ime)`
- 同时检查 `OutlinedTextField` 是否用了 `TextFieldValue` 且**保留 selection**——若每次输入重建 `TextFieldValue` 而丢掉 selection，光标会跳到末尾，同样表现为"打字时乱动"

### F-1 输入过滤 — 当前代码中不存在 ⚠️

查了五个层面，**全部无字符过滤**：

| 层面 | 位置 | 结果 |
|---|---|---|
| 输入框回调 | `ChannelHubScreen.kt` 全部 `onValueChange` | 均为直接赋值（`:1285`/`:1286`/`:1481`/`:1484` 等） |
| 输入限制 | 全项目 `InputFilter` / `digits` | 零命中 |
| 键盘类型 | `KeyboardOptions` / `KeyboardType` | 零命中 |
| 全局清洗 | `sanitize` / HTML 转义 / 尖括号校验 | 零命中 |
| 保存解析 | `parseCustomHeaders`（`MultiChannelForwardWorker.kt:1191`） | 只解析 JSON / Key:Value，不过滤字符 |

**结论**：该 bug 在当前代码（目录 `1.0.4`，CHANGELOG 最新 `1.1.7`）中**找不到对应实现**。两种可能：

1. 用户所用版本与当前代码不一致（用户说"吃上 1.7"，需确认 1.7 对应的版本线——本项目 CHANGELOG 是 1.1.7）
2. 非代码层原因（输入法、ROM 定制键盘）

**建议**：向反馈者确认**具体版本号 + 机型 + 输入法**；若确为 1.7，需在对应代码线复查。**不要在当前代码里凭空造一个过滤再去修它**。

## 五、一个值得记录的模式

本次从"用户截图"到"代码定位"的过程，暴露了一个和复审同样的规律：

**测试全绿 ≠ 问题不存在。** F-2 的根因（全项目无 `imePadding`）是 87 个单元测试永远发现不了的——它们测的是逻辑，不是布局。而 F-1 反过来更极端：**当前代码里根本找不到这个 bug 的实现**，如果不去核对就"修"，就会凭空造一个过滤再把它删掉。

两类问题的共同点是：**它们都位于"测试的盲区"**——一类在渲染层，一类在版本差异层。判断它们只能靠人读代码 + 与反馈者核对信息。
