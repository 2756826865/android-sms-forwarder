# 机器人白名单 ID 申请 · 2026-10-10

已在源码接入钉钉、飞书、企业微信智能机器人、Telegram。私聊发送“申请用户白名单”；群内 @机器人 发送“申请群白名单”。支持“申请群主白名单”别名，但返回群会话 ID，不验证群主身份。

| 来源 | 用户白名单值 | 群组白名单值 |
| --- | --- | --- |
| 钉钉 | senderStaffId优先，缺失时senderId | conversationId |
| 飞书 | open_id优先，缺失时user_id或union_id | chat_id |
| 企业微信智能机器人 | from.userid | chatid |
| Telegram | user_id | chat_id，保留负号 |

请求在短信命令解析和白名单授权之前单独分流。来源必须已启用、凭据有效；回复前复查来源与当前运行实例。申请只显示本次事件ID，不添加授权，不执行短信，不修改发信限额。群聊没有@时不回复，私聊群申请提示去目标群。原有短信授权路径保持独立。

同一来源/会话/用户30秒限一次；回调ID短期去重、缓存有界。长连接来源的回复使用独立有界执行器，避免等待HTTP或企微ACK阻塞回调线程。钉钉先ACK消息，再调申请回调；HTTP回复设置超时并关闭重定向。日志记录回复状态，不写Token、会话Webhook或申请ID。

## 验证

18项JUnit测试通过，结果见test-results/whitelist-id-requests-2026-10-10.log。复现脚本：tools/whitelist-host-tests/run.py；依赖与范围见同目录README.md。

- 8项请求格式、ID、私聊提示、群聊@、限流和重复检查。
- 3项真实钉钉Stream入口的本地消息回放：先ACK、申请不分流到短信、群主别名。
- 4项企微/飞书真实入口元数据映射、Telegram ID格式及群聊/缺少回复目标保护。
- 3项宿主集成检查：Telegram在本地HTTP端点原会话回复、关闭来源不执行、运行时拒绝关闭/配置变化/失活的实例。

针对性测试使用实际来源类和运行时管理器，Android存储、来源仓库、短信引擎及无关服务使用隔离测试替身；没有真实机器人凭据或短信发送。Compose帮助页面只做文字检查，未执行完整Android构建。本轮没有构建完整APK、没有生成安装包。真实平台权限、投递/@条件、设备后台、实际ID和原会话回复仍需真机验收。

邮箱、短信、普通Webhook转发及自定义WebSocket未接入此机器人信息申请功能。
