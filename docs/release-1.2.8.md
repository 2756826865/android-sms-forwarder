# 短信转发器 1.2.8（发布说明草稿）

版本代码：1218。上一轮已验证代码基线：`f30696282ba8791b2e9fff2830946e5eb032e05d`。状态：1.2.8 分支测试版，尚未合并 main，尚未发布正式 GitHub Release。

- 接收链路加入加密暂存、持久化接收记录和异常恢复，系统写入结果不确定时先核对，不盲目重复插入。
- 快速提交本地消息与会话；两套主页通过 Room 变化更新列表，连续收信时合并补读，转发不等待页面绘制。
- 联系人补全独立执行，保护消息正文、已读和接收卡信息，补齐有界重试及失败记录。
- 历史短信按 500 条分页写入缺失记录，未完成导入可重新补导；恢复扫描去重并确认修复结果后推进检查点。
- 接收卡识别优先采用真实接收证据，未知卡不猜测；转发和重试保留原始目标、SIM 与任务所有权。
- 配置错误与接收记录隔离，相同凭据重新加密不应被视为换目标；不可安全确认的历史转发保留核查状态。
- 增加通知补偿、前台验证码提示、保活实际状态诊断，以及远程连接网络变化后的重连唤醒。
- 广播超时不再无限持有系统令牌，也不伪装成持久化成功；彻底的存储、密钥或资源故障仍可能导致接收无法确认。

## 本轮追加的四项联动修补

- 取消小米、OPPO 和通用 Live Update 适配对整条通知的自动过期设置；小米仍保留岛展示时长。
- UI 补偿按已匹配的目标 ID 严格补齐，不再依赖最近 50 条窗口恰好包含目标。
- 实际发布时以通知栏中同会话的已发布消息作为替代证据，过滤短信不再仅因较新、未读而压掉合法通知。
- 开发版和经典版设置接入同一验证码弹窗偏好，两套首页在显示前复核开关；关闭不影响后台通知或短信转发。

本轮新增 4 项通知顺序 JVM 测试、2 项 Android 设备测试，实际 UI 补偿 Worker 的主机模拟场景增至 25 项。构建及设备结果以本轮修补提交的工作流为准；以下是历史基线的验证记录。
