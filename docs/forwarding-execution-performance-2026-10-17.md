# 转发执行与性能优化（待发布）

本批次保持最低 Android 版本不变。QQ群跳转和手动检查更新为此前待发布改动，本文件记录执行与性能优化。

## 模板

- 规则模板只解析实际使用的联系人、电池、网络、IP、时间及验证码标签。
- 一次规则渲染共享接收SIM快照；电池百分比和完整电池信息共享一次读取。
- 保留现有模板别名和标题显示行为；普通通知标题需要联系人名称时仍会正常读取。

## 转发历史

- 新增独立 SQLite 数据库 forwarding_history.db，不改变短信数据库的 Room 版本。
- 首次使用在事务中导入原 forwarding_history/records JSON，迁移标记与导入共同提交。原偏好数据保留，清空显示日志不会再次导入。
- 状态改变只更新对应行。首页用 SQL 统计和最多30条近期记录；短信补偿只读取 work_id 列。
- 经典日志页取消1.5秒轮询，前台监听刷新事件并合并150毫秒内的事件。初次50条，按需加载更多。
- 完成日志保留上限由200提高为2000；未结束任务不因日志数量上限而删除。统计基于保留的日志。

## Webhook

- 兼容已有 HTTP 2xx 成功规则，新增“响应包含”和“JSON字段等于期望值”，如 code=0、data.success=true。
- 测试发送与生产发送使用同一个成功条件实现。HTTP非2xx不能被正文中的成功字符串覆盖。
- 不额外新增代理或PATCH等传输能力。

## 通道组与重试

- 统一通道编辑器新增通道组，作为规则中明确选择的目标，不加入默认全通道广播，避免成员与组重复发送。
- 支持全部并行发送、按顺序成功即停止、按顺序失败即停止；顺序组最多16个直接实例，不支持嵌套。
- 每步执行前重新检查组和当前实例开关。请求结果未知时停止顺序组，不自动重试或切换。
- 传输读写异常、超时单独标记结果未知；初始连接失败、域名解析失败与明确接口拒绝单独处理。
- 组执行标记与用户可清空的展示日志分开保存。进程重启发现上一步请求处于运行状态，保守停止为结果未知。
- 日志提供“仅重试此通道”：保存完整实际入队正文、目标和接收SIM快照。手动确认后仅重试原目标，不重新匹配规则或重跑整个组。
- 旧日志没有完整投递数据时拒绝使用截断正文重发；结果未知的重试可能重复投递，需用户确认。

- 实际生产与测试Webhook方法通过8次本地HTTP联调。
- 日志存储、经典日志页、组调度与重试接口做了宿主编译检查；无关Android/WorkManager依赖使用桩。

## 保活与空闲扫描优化（未发布）

- SmsKeepAliveService 在 START_STICKY 恢复时重新核对保活开关和默认短信身份；不满足条件时移除前台通知并停止，不再返回 START_STICKY。ensureStarted 遇到不满足条件时也主动停止旧服务。
- SmsRecoveryWorker 的本地短信 ID 集合和已转发记录集合改为每次扫描内按需加载；查询无短信时不再读取这两个集合。保留补偿时间窗口、去重规则和 15 分钟调度频率。
- 六类远程指令服务只在创建时发布前台通知，不再每次 onStartCommand 重复发布同一通知；通知明确区分监听服务运行与网络连接状态，实际来源连接状态继续由运行管理器维护。
- 复查确认远程服务已有来源开关及凭据校验，运行管理器已有实例和配置指纹去重，本次未叠加新的守护或轮询机制。

验证：七个实际服务源码通过 Kotlin/JVM 编译（Android 37 API，项目依赖使用替身），git diff --check 通过。补偿集合的惰性加载进行源码路径检查；尚未完整构建 APK，也未进行真机杀进程、短信接收或待机耗电测试。


## 按需短信处理与失败兜底（未发布）

- 未保存过 keep_alive_service_enabled 时默认 false；已有明确 true/false 配置继续生效，不覆盖用户选择。界面改称“兼容保活模式”，关闭时明确说明收到短信后处理、完成后结束。
- 普通短信仍交给短时 IncomingSmsService，保留完整通知、规则及其他短信能力；完成后 stopSelfResult，不把 processMinimal 作为日常主路径。
- SmsReceiver 交接遇到未预期 Exception 也执行已有最小处理兜底，finally 始终释放广播令牌。
- 短时处理服务在处理抛异常时补充最小处理及 SmsRecoveryWorker 入队，不再仅依赖“未获得前台身份”的条件触发补偿。
- 现有 WorkManager 网络约束、指数退避、定期补偿及投递结果未知时防止重复发送的策略不变；远程监听由其来源开关独立管理，不自动替用户打开常驻保活。

验证：14 项配置/通道仓库 JUnit 测试通过，包含默认按需和明确选择持久化；实际 SmsReceiver 源码在宿主替身环境通过 9 个交接场景（两种短信 action 的成功、拒绝、异常、保活失败，以及意外 action）。git diff --check 通过。完整 APK 构建和真机锁屏、系统回收、断网恢复验证尚未进行，不能保证 OEM 限制或强行停止后自动唤起。
