# 会话收件人 ID 溢出修复（实现记录）

基线：main `e0531e078935e3e2215608e263bb4d197a1a839f`。原独立分支 `fix/recipient-id-overflow` 保留，补丁已合入 `1.2.4(101901)` 构建候选。以下为本地验证记录，后续构建发布状态以 GitHub Actions / Release 为准。

## 问题与处理

原来列表和参与者读取各有一处将 `recipient_ids` 直接转为 Int，长数字会抛出 NumberFormatException，且可能中断整批列表读取。

- 系统 canonical-address ID 全程作为字符串传入参数化查询；不把它当作电话号码，不截断为 Int/Long。
- 会话列表、详情、彩信参与者与快捷方式使用共同解析逻辑，保留 ID 与号码的对应关系。
- 单收件人 ID 缺失、格式异常或查不到地址时，从实际短信 ADDRESS 字段兜底，保留号码前缀、前导零和文字发件人。
- 多人会话不能完整解析时，不用单个短信发件人替代整个会话，不返回错位或缺失成员的参与者列表；列表保留已有会话缓存。已有彩信的参与者不会被空结果覆盖。
- SimpleContact 仍使用 Int 字段；超出范围的系统地址 ID 不再强制转换，使用原有未知联系人 ID 0，不发生数值截断碰撞。
- 厂商 Provider 内部再次抛出 NumberFormatException 时，将该地址视为未解析，继续走上述兜底。

没有改动短信发送、SIM 选择、转发规则、隐私处理、系统短信数据库或 KSU 模块。

## 验证

- 新增 12 项 JVM 回归测试：反馈中的长 ID、超过 Long 的 ID、普通/大 ID 混合、号码兜底、异常字段、空白分隔、多人缺失与联系人 ID 边界，均通过。
- 提取实际列表/参与者读取函数，在隔离环境以 Provider/数据库替身完成 6 个场景检查，包含列表继续读取、参数原样传递、Provider 内部溢出、空地址兜底、参与者 ID 不截断，以及未解析群聊保留会话缓存，均通过。
- 正式构建工作流已将新增单测列入回归清单；未触发该工作流。
- 未完成完整 APK 编译和 Android 真机验证；隔离环境结果不能代替厂商 Provider 实测。截图没有完整堆栈，修复的是源码中已确认的同类缺陷。
