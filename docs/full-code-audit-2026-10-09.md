# 2026-10-09 全仓风险巡检与修复记录

## 范围与证据边界

本轮对仓库 app/src/main/kotlin 下 358 个 Kotlin 文件进行路径盘点和风险模式搜索；对短信发送/回执、会话选卡、远程命令、同步、转发回执与重试、SMTP、规则和配置恢复的主要调用路径进行了人工阅读。不是逐行覆盖证明，也不是全部功能测试完成。保留现有未提交改动，没有重置源码或推送。

## 本轮新增修复（不重复计算此前 SIM3 与卡名称补丁）

| 编号 | 确认缺陷 | 修改 |
|---|---|---|
| A01 | 远程指令固定 SIM1/2 仍 allowFallback=true，指定空卡槽可能改用另一张卡 | 固定卡槽禁止回退；解析不成功的 Worker 不调用默认卡发送 |
| A02 | 定时短信“立即发送”无条件删除任务，发送前校验或提交失败仍丢失任务 | 仅提交成功后清理任务；未提交时保留原记录 |
| A03 | 各长短信分段单独覆盖整条短信状态，成功分段能覆盖失败 | 用真实回执持久化聚合；全部成功才成功，失败优先；每次发送有独立回执关联 ID，关闭影子诊断仍工作 |
| A04 | 发信回调接收器把数据库操作丢到后台但没有 goAsync 生命周期保障 | 增加 goAsync/finish；发送和送达的核心处理不再二次脱离受保护线程 |
| A05 | 远程回执在发送 API 返回后才注册，快速回调可能丢失 | 注册移到真实发送前；同步提交异常清理本次等待回执 |
| A06 | 企业微信远程发送诊断触发源写成钉钉 | 独立 REMOTE_WECOM_COMMAND，不改变企业微信连接或消息协议 |
| A07 | 群发 Worker 捕获 CancellationException 为普通发送错误 | 继续传播取消，停止后不继续下一号码 |
| A08 | 迟到的“已提交”状态会覆盖已发送/失败/已送达 | 发送影子状态保留终态；远程命令 SQL 防止 SUBMITTED/SENT 倒退，真实 SQLite 8 个场景通过；分段影子记录在 API 前建好 |
| A09 | 本地发送预插入就写 MESSAGE_TYPE_SENT，与 Provider OUTBOX 不一致；同步抛错只更新 Provider | 预插入 OUTBOX，提交异常同步更新本地失败状态 |
| A10 | 拒绝电话权限后直接关闭会话，用户无法使用重试/授权入口 | 保留会话浏览和未知 SIM 入口；发信仍校验权限和有效订阅 |
| A11 | 送达 PDU 中间/无效状态被当失败清理回执，送达时覆盖 DATE_SENT | 无效 PDU 不推进结果；中间状态继续等待，最终状态才通知；保留原发送时间 |

附带修正：远程短信已提交后的诊断关联查询使用 fail-open，查询异常不冒充实际提交失败。

## 已检查但未找到本轮确认缺陷的路径

- 备份恢复：v1-v3 输入结构预检、加密恢复前快照、失败回滚和恢复后重新连接。仍不是跨存储原子事务，也不等于全量短信备份。
- 规则：优先级参与匹配、未知卡槽条件不冒充 SIM1、无效正则安全处理、模板及替换的实际执行路径。
- SMTP：SSL/STARTTLS、握手时主机名校验、收件地址校验、SMTP 多行响应终止判定。
- 转发调度：已有成功通道时不整批自动重试，避免重复提交；永久配置错误与短暂错误分流。未使用真实凭据发通知。
- 同步：进度有防并发状态和 finally 收尾，开发版保留缓存列表。系统 Provider 内部把部分异常变成空结果仍会降低错误可观测性，记录为待改进，不据此删除用户缓存。
- Root 守护：静态查看启动/停止和进程退出处理；不证明厂商 ROM 保活效果。

4. 新分段持久化聚合需确认重启、乱序、多分段失败及重复回调；无终态回调时保持发送中，不能推断已送达。
