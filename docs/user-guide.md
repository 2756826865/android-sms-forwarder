# 短信转发器使用教程与排障

QQ 交流群：**569321348**。关于页面可点击群号复制。经典版和开发版均复用同一通道教程；开发版通道页顶部「教程」，经典版远程发送页「使用教程」，两版「关于 → 使用教程与排障」。

以下按当前源码说明能力，不代表所有通道均已真机验证。已由用户确认正常的微信智能机器人、PushPlus、企业微信、钉钉路径，本轮没有改变其接口协议。

## 先区分三条链路

- 接收转发：系统收到 SMS → 接收广播 → 拦截/规则/模板 → 具体通道实例 → WorkManager 调度 → 平台接口 → 受理回执。断网任务可能延后。
- 远程发信：平台事件/轮询 → 来源鉴权与白名单 → 指令解析/限额/规则 → 物理卡槽映射 → 系统短信 API → 发送回调 → 可选运营商送达报告 → 来源或指定通道回执。
- 历史同步：系统短信 Provider → 本地短信/会话缓存 → 列表、正文搜索与统计。普通刷新不是全量同步；全量同步不应重新外发所有旧短信。

## 转发通道配置清单

同一类型可保存多个实例。先保存并测试，再启用实例、在规则选择具体实例。平台成功受理并不保证手机已弹通知。

| 通道 | 凭据、目标与配置方式 |
|---|---|
| PushPlus | Token；群组再填 Topic。HTTP API，检查业务返回，测试后在微信查收。 |
| WxPusher | AppToken，接收者 UID 或 Topic ID；接收者先关注应用。 |
| 微信测试号 | App ID、App Secret、关注者 openID、模板 ID；模板字段须与平台一致。 |
| 企业微信应用 | 企业 ID、AgentId、应用 Secret、成员 User ID；成员属于应用可见范围。 |
| 企业微信群机器人 | 完整群 Webhook；属于单向通知，不能代替智能机器人远程来源。 |
| 企业微信智能机器人 | 已启用的长连接来源、会话 ID；先确认来源鉴权及连接可用。 |
| 钉钉群机器人 | Webhook、可选加签 Secret；满足机器人关键词/签名等安全设置。 |
| 飞书群机器人 | Webhook、可选签名 Secret；群机器人不是长连接自建应用。 |
| 飞书自建应用 | App ID、App Secret、接收者 open_id；机器人能力、发送权限及可见范围。 |
| QQ | Qmsg 填 Key；OneBot11/NapCat 填 HTTP 服务地址、可选 Access Token、user_id 或 group_id；仅转发。 |
| Server酱³ | SendKey，按服务商要求安装并授权接收客户端；勿与旧版 SCT 配置混用。 |
| Bark | 服务地址、Device Key；可自托管，HTTP 必须按界面允许范围配置。 |
| Gotify | 服务地址、应用 Token；当前响应必须包含有效消息 id。 |
| ntfy | 服务地址、Topic、可选访问 Token；私有主题需要服务器授权。 |
| 邮件 SMTP | 主机、端口、SSL/TLS 或 STARTTLS、账号、密码/应用授权码、收件人。 |
| Telegram | Bot Token、Chat ID；用户先启动 Bot，群聊需添加 Bot。 |
| Discord | 频道 Webhook；受频道和服务商限流约束。 |
| WebSocket | 自建服务端地址、可选 Token；使用本应用协议，不能当作通用 OneBot客户端。 |
| 腾讯云自定义告警 | 告警回调地址和 Secret；云端配置决定后续通知，接口受理不等于短信送达。 |
| 短信直发 | 目标号码、发送卡及费用限制；实际调用本机 SIM，可能按长短信分段计费。 |
| 自定义 Webhook | 地址、HTTP 方法、Content-Type、Headers、正文模板；成功判定以当前实现和服务端返回为准。 |
| 通道组 | 多个具体实例组合；不能循环引用；聚合不等于新增平台。 |

邮件不限 QQ 和 163：只要服务允许现有账号密码认证，可填自定义 SMTP。SSL/TLS 常用 465、STARTTLS 常用 587，最终按服务商文档选择。多个收件人用英文逗号或分号分隔。仅允许 OAuth2 的账户不支持；企业租户可能关闭 SMTP AUTH。SMTP 受理后仍可能退信或进入垃圾邮件。

## 远程发送：当前实际支持 7 类

短信指令、钉钉 Stream、飞书长连接、企业微信智能机器人、Telegram 长轮询、WebSocket、邮箱 IMAP。QQ/OneBot 没有远程来源实现；企业微信应用号是转发通道，不能当作智能机器人来源。

指令示例：

```
/发信 10086 1
/发信 SIM1 10086 1
/发信 SIM2 10086 1
/发信 默认 10086 1
```

省略卡槽时使用来源的发送卡设置。SIM1/SIM2 是物理卡位，不是订阅 ID；订阅 ID 随换卡可能变化，不能用 ID 加一显示卡槽。固定卡失效时应报错，不能悄悄换卡。自定义卡名称/号码只控制显示。

新建网络来源默认白名单关闭；开启后才要求授权用户，群聊还需授权群 ID。旧配置的已有开关保留，不要在升级时自动开放。填写真实事件 ID，不填昵称；短信来源填号码、邮箱来源填邮箱地址。启用白名单后留空会拒绝请求。

### 机器人白名单 ID 申请

钉钉、飞书、企业微信智能机器人、Telegram 支持同样的申请指令：群里 @机器人 发送 `申请用户白名单` 或 `申请群白名单`；有私聊入口时也可私聊申请用户 ID。也支持 `/白名单`、`申请群组白名单` 与 `申请群主白名单`。群主别名只查询群组ID，不验证或授予群主身份。

| 渠道 | 回复的用户 ID | 回复的群组 ID |
| --- | --- | --- |
| 钉钉 | senderStaffId 优先，缺失时 senderId | conversationId |
| 飞书 | open_id 优先，缺失时实际事件的 user_id / union_id | chat_id |
| 企业微信智能机器人 | from.userid | chatid |
| Telegram | 数字 user_id | 数字 chat_id，保留群 ID 的负号 |

申请人不必已在名单中，但来源必须已启用且凭据有效。回复只展示本次事件的ID，须由设备管理员在对应来源手动添加；不会自动授权、不会消耗短信发送额度。私聊申请群白名单时提示到目标群申请。群聊要 @机器人；飞书还需成功识别本机器人的 open_id，无法确认被@时不猜测。企微群聊的@标记按现有平台回调行为识别。

同一来源、同一用户、同一会话30秒内最多回复一次，重复回调在5分钟内去重，缓存各最多200项；进程重启会清空这层信息回复缓存。钉钉/飞书/企微回复使用有界异步队列，避免等待回执阻塞长连接。Telegram在其轮询线程原路回复；群聊隐私模式及平台的消息投递条件仍需满足。申请响应独立于“短信回执转发”开关。

短信、IMAP邮箱、普通Webhook转发通道没有此机器人申请回复入口；WebSocket自定义服务也未接入这一指令。原有发信授权逻辑继续生效。

### 钉钉 Stream

1. 在开发者后台创建组织内部应用，取得 Client ID 和 Client Secret。
2. 添加机器人能力，消息接收选择 Stream，发布并确认可见范围。
3. 本应用远程发送新建钉钉来源，保存并启用，等待连接就绪。
4. 私聊发送示例指令；群聊添加机器人后 @机器人发送。
5. 在目标群 @机器人 发送“申请用户白名单”或“申请群白名单”；有私聊入口的平台也可私聊申请用户 ID，机器人会回复可复制的用户 ID 和群会话 ID。用户优先用 senderStaffId，缺失时用 senderId；群组用 conversationId。填写到该钉钉来源的对应白名单，每行一个完整 ID。
   - 未在白名单中的用户也能申请获取本次消息的 ID，但不会自动加入白名单或触发短信发送。
   - “申请群组白名单”“申请群主白名单”是群申请的别名；返回的是群会话 ID，不验证或授予群主身份。
   - 私聊申请群白名单时会提示到目标群 @机器人。群内未 @机器人不回复此申请。
   - 同一用户在同一会话30秒内最多回复一次；重复回调短期去重。回复原路发送，独立于短信回执开关；来源仍需保存并启用、连接就绪。
6. 检查发送卡、发送权限及回执。群机器人 Webhook 不能接收 Stream 指令。

官方参考：https://open-dingtalk.github.io/developerpedia/docs/explore/tutorials/stream/bot/go/create-bot/

### 飞书长连接

1. 创建企业自建应用，开启机器人，复制 App ID 与 App Secret。
2. 配置机器人收发所需权限；订阅接收消息 v2.0（`im.message.receive_v1`），选择长连接接收事件。
3. 在本应用创建来源并启用连接；后台若提示先建立连接，保持客户端连接后再保存订阅。
4. 发布应用版本，确认安装及成员可见范围。
5. 私聊测试；群聊添加机器人并 @它。白名单使用 open_id / chat_id。
6. 连接就绪但无事件时，先查应用是否发布、事件及权限是否生效，不要反复重新填凭据。

官方参考：https://open.feishu.cn/document/server-docs/im-v1/message/events/receive

### 企业微信智能机器人

创建支持 API 长连接的智能机器人，复制 bot_id 与 secret；来源保存启用后等待鉴权和连接成功。私聊指令或群内 @机器人测试。授权用户 ID 与会话 ID 取实际事件/回执，不能用手机号猜测。企业 ID、AgentId 和应用 Secret 属于企业微信应用消息，不能混填。

### Telegram、WebSocket、邮箱与短信

- Telegram：BotFather 创建 Bot，用户先与 Bot 对话。长轮询与 Webhook不能同时使用，也不要多个客户端同时消费 getUpdates。白名单填数字 user_id/chat_id。
- WebSocket：填写服务端 ws/wss 地址与 Token；公网优先 wss。先对照 `WebSocketRemoteClient.kt` 的请求字段和响应协议，不能直接接入任意第三方机器人协议。
- 邮箱：开启 IMAP，填写主机、端口、账号和授权码；隐式 TLS 常用 993，STARTTLS 按服务商设置。轮询 INBOX 中未读邮件的主题和正文，不保证瞬时；已读邮件不在该轮询范围。先用纯文本指令验证；附件和复杂 MIME 不能视为全部支持。它与 SMTP 转发是独立配置，OAuth2-only 不支持。
- 短信：允许读取/接收权限；指定前缀和授权号码，避免指令来自转发回流。真实发送产生短信费用。

## 回执和重试

系统 API 接收、发送成功、最终送达是三个状态。原路回执适用于钉钉、飞书、企业微信智能机器人、Telegram、WebSocket；短信/邮箱按配置选择回执转发目标。运营商不提供送达报告时，等待状态不能当成失败并无限重发。

网络转发 Worker 当前只在无成功目标、不是永久错误、未达到次数限制时重试；服务商已经受理但响应丢失仍可能出现歧义，不能保证绝对一次投递。远程短信提交之后不应根据超时自动重发。长正文受平台字数、分段和 WorkManager 数据大小约束；当前转发正文有明确截断标记。

## 两版入口与备份

两版共享短信数据库、配置和执行组件；入口不同不代表每个界面都具有同样交互。

- 经典版：设置 → 备份与恢复、系统兼容及关于；通道入口打开共用通道管理页。
- 开发版：运维依次是后台运行、链路诊断、诊断报告、备份与恢复、更多设置、运行日志。
- 备份可导出 JSON 文件并选文件导入，也保留剪贴板方式。导入先预览并生成本机恢复快照；失败回滚不能称为跨存储原子事务。
- 配置备份不包含系统短信正文历史、系统授予权限和所有系统设置。导出文件含通道凭据，别发到公开群。
- 开发版全量同步在消息页更多菜单；普通刷新只刷新列表。正文搜索基于已同步本地数据且有结果上限。
- 回收站保存本应用删除的短信，不是系统拦截箱。文件恢复、换卡、三键导航及 Root 守护仍需设备验证。

## 排障顺序

先确认系统权限/默认短信角色，再查收到短信或平台事件 → 规则/白名单 → 来源卡位映射 → 队列 → 平台业务结果 → 收件客户端。发送失败「服务不可用」要查信号、SIM、默认发送卡和系统短信服务，不只看按钮是否显示。

GitHub反馈：https://github.com/2756826865/android-sms-forwarder/issues 。附版本、机型系统、两版入口、可重复步骤和脱敏诊断。不公开凭据、验证码、备份或完整手机号码。
