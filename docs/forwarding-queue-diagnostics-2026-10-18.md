# 移动数据转发排队：入队检查与按需诊断（实现记录）

基线：已发布的 1.2.4(101801)。下文为本地验证记录；补丁已进入 `1.2.4(101901)` 构建候选，后续结果以 GitHub Actions / Release 为准，保留旧版安装包。

## 用户看到的变化

- 提交发送任务时记录“正在提交”，收到 WorkManager 异步结果后再确认已提交系统调度。
- 提交异常不再只留下“队列中”；保守显示“结果未知”，提醒先检查实际任务，避免重复发送。
- 转发日志中可点击“查看排队原因”，读取实际任务状态、延迟/重试时间、网络系统验证状态、省流量模式和系统报告的后台限制。
- 运维链路诊断同步展示上述快照；旧日志按原唯一任务名查询，新任务通过日志 ID 标签关联。

## 边界

“测试”直接联网成功，不代表 WorkManager 的真实转发任务已获调度。当前源码使用 CONNECTED，没有仅 Wi-Fi 或运营商判断。未通过系统网络验证是一个可能的等待原因，不能据此断定通道无法联网。

本次修复入队结果记录缺口、增加按需诊断，并在日志页面打开与既有短信恢复检查时核对实际任务状态。日志页面只同步，不发送；既有恢复任务可对符合严格条件的任务补交一次。没有改变真实发送入口，没有取消网络约束，没有新增周期任务或常驻监听。兼容保活仍默认关闭，保留已保存的选择。

异步提交状态回调只更新尚未启动的 queued 记录，不覆盖 running / retry / success / failed / skipped / unknown。确认写日志失败不会被误当作入队失败。Operation 失败也不能充分证明任务未落库，因此不据此自动补发。2026-10-19 补齐：回调完成后核对系统实际任务 UUID，仅绑定实际保存的请求快照；一次补偿的新 UUID 也须实际保存后，按原快照比较更新绑定。手动重试核对快照 UUID 与实际任务一致；KEEP 忽略的新请求不覆盖原请求的正文、路由和恢复数据。重复登记不重置已有投递状态和尝试次数。

诊断不包含短信正文、号码、凭据、SSID 或任意通道错误正文，查询总等待上限 5 秒。查不到任务超过提交宽限期后，将未决日志更新为结果未知，不推断已送达，也不自动重发。实际仍有效的任务继续由原 WorkManager 执行。

自动补偿仅限：原任务明确为 FAILED、系统及本地均无启动记录、非测试/非通道组/非收费短信直发、24 小时内、保存了新格式完整原始 WorkData、与失败任务 UUID 一致且尚未补偿过。原始实例、正文、SIM 快照、规则模板、隐私处理、原定最早执行时间均保留；不重新匹配规则。不恢复主动取消的任务，不自动恢复旧版缺少完整快照的任务。任务结束却没有明确通道结果时只标未知。

新增独立的一次补偿标记，事务内认领后再按原唯一任务名 KEEP 提交；清理展示日志不会清除标记。认领后崩溃不重复补交。历史数据库无损升为 v3，保留 v1→v2→v3 的增量迁移，增加检查时间、单独的队列观察详情、补偿及手动重试预约表，短信数据库不变。队列核对不再覆盖原始发送错误。检查采用快照比较，异步写入不覆盖并发到达的成功结果；检查时间轮转避免旧的有效排队任务阻挡其他记录。

结果未知的提交也纳入只读状态核对；存在活动任务时继续观察原任务，不因 Operation 报错而另建投递。手动重试前查询原唯一任务名和旧重试任务：活动、已成功、查不到或查询失败/超时均阻止提交；仅确认原任务 FAILED/CANCELLED 后允许用户明确重试。预约与原记录快照比较在同一事务内完成，避免连续点击及自动补偿竞争。每个原记录只允许一次手动重试；后续需查看新重试记录。原实例删除、停用、类型改变时停止，且手动重试与补偿任务不切换备用目标或展开通道组。

任务快照在实际任务确认保存后写入；若此间进程终止，快照可能缺失。这种情况不自动补交，也不能从缺失完整数据的日志重试，优先避免重复发送。手动重试预约成功后若进程终止，也不释放预约自动重投。

尚未确认客户手机的根因。本次不是“移动数据排队已修复”的结论。

## 本轮验证（2026-10-19）

- 含收费短信策略、队列判断、异步观察、补偿边界的 57 项 JVM 策略检查通过；实际 WorkManager 2.11.0 Data 序列化与恢复另 1 项通过，保留原短信去重标识。
- SQLite：队列迁移/原快照保留/预约/详情分离 11 项、收费去重库 4 项、既有历史 7 项、电量查询 4 项、会话 SQL 4 项通过，共 30 项。
- 实际调度器在 WorkManager API 替身环境完成 14 项执行检查，含 KEEP、提交报错但已保存、查询失败、历史写入失败、异步快照冻结及取消。
- 实际存储方法在 Android SQLite API 替身环境完成 11 项检查，含原错误保留、快照绑定、旧观察不覆盖新结果、并发预约、自动/手动预约竞争与清日志保留标记；SQL 本身另由上述真实 SQLite 测试验证。
- 实际重试/Outbox/短信直发入口共 35 个宿主场景通过，均未发送真实短信或访问真实通道。
- 实际 Worker companion 入队代码、调度器、重试入口、补偿器已对 WorkManager 2.11.0 产物编译核对；Android Context/Log、非目标配置依赖等使用宿主替身。这不是 Android SDK 完整编译或实际设备运行证据。
- 本轮没有完整 APK 编译，也没有真机锁屏、移动数据验证；本地缺少可用 Android SDK。

## 真机验证步骤

1. 关闭 Wi-Fi，保持移动数据及应用前台，接收一条测试短信。
2. 若排队，进入转发日志，点击该通道“查看排队原因”，保存快照。
3. 锁屏后接收另一条短信，重复读取快照；如任务已执行，查看实际发送结果。
4. 记录机型、系统、版本与兼容保活开关。对照系统验证、后台限制、实际任务状态和最早执行时间定位原因。
5. 对结果未知的任务先检查接收端，不重复点击发送。
