# 1.2.5 收信界面刷新回归修复（候选版本）

基线：`16b1349a`，已发布 `1.2.5(102201)`。本轮代码修复放在独立分支，候选版本 `1.2.5(102401)` / 1213，未覆盖正式 Release。

## 已确认的问题

- 非默认／Provider 写入失败的降级收信分支缺少独立的本地同步与界面更新机会。立即恢复扫描可能早于原生短信应用落库，也不能保证即时 UI 更新。
- 恢复扫描使用 `alreadyLocal || sms-minimal-前缀` 防止远程指令和通知重放，但错误地将该条件用于决定是否同步本地数据：降级任务尚未进入 Room 时也会跳过会话同步。这是 1.2.5 整合的遗漏。
- 1.2.4 的系统写入失败分支本来就会提前返回，不能据此声称旧版无论如何都能写入 Room。非默认状态下恢复强写系统库、向现有消息表写入虚构系统 ID 都不是本补丁的处理方式。

## 修改

- 本地缺失且真实 thread ID 有效时，恢复扫描始终补同步，与防重复转发／执行指令的判断分离。
- 新增只读 UI 同步任务。降级无法写系统库、成功写入后本地同步失败、接收预算耗尽时触发；同一收信指纹使用 KEEP，避免并发重复排队。
- 只保存收信时间、订阅 ID 和号码／正文的 SHA-256 摘要，不在新 WorkData 中保存短信原文。
- 仅查询该收信时间附近的系统收件箱，最多检查 256 行，核对内容与可用订阅 ID；使用真实 message/thread ID 同步现有会话，确认本地记录存在后再发列表和详情刷新事件。
- 每轮最多四次短查询、间隔 250ms；未落库时最多四轮 WorkManager 执行，指数退避。无长期轮询、网络约束或常驻服务。撤销 READ_SMS 时停止，取消继续传播。
- UI 任务不提交／发送短信、不重新匹配转发规则、不消费远程命令、不弹新收信通知；原转发和收费防重保护保留。

## 验证和边界

主机回归直接编译实际 `IncomingSmsUiSyncWorker`，Provider、WorkManager、Room 和界面事件使用替身。16 个场景覆盖即时／延迟落库、双卡隔离、未知及空订阅、内容不匹配、无效 ID、缺权限、读取时撤权、空查询、重试耗尽、无实际同步、取消、无效输入、查询上限与任务键／原文保护。

该测试不等于 Android 真机验收；实际项目 Kotlin/Android API 编译、完整单测与签名构建由候选分支 CI 执行。

仍需设备验证：默认及非默认状态收到短信后，主页置顶、已打开详情页追加消息；原生应用延迟入库；关屏后恢复前台；同文不同 SIM；确认不额外推送、不重复执行收费指令。若系统根本未保存短信或未授予读取权限，本补丁不伪造短信记录，也不能承诺界面实时展示。
